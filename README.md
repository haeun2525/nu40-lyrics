# NU40DK 가사 디스플레이

노래를 노트북에서 재생하면서, 그 타이밍에 맞는 가사와 주파수 막대를 NU40DK의
SSD1306 OLED(128x64)에 띄운다.

```
YouTube 링크 ──yt-dlp──▶ m4a ──afconvert──▶ WAV ──numpy STFT──▶ 16밴드 막대
                          │                                        │
                          └── afplay ──▶ 노트북 스피커              │
                                                                   │
  .lrc 가사 ──lrc.py──▶ 화면 폭에 맞게 자른 조각 ────────────────┐  │
                                                                │  │
                                        USB 시리얼 30fps ◀───────┴──┘
                                             │
                                        NU40DK ──▶ OLED
```

**보드는 소리도 인터넷도 없다.** 다운로드·분석·타이밍 계산·재생은 전부 PC가 하고,
보드는 받은 대로 그리기만 한다. 주식 티커와 같은 역할 분담이다. 이걸 바꾸지 말 것.

## 구성

| 파일 | 역할 |
|---|---|
| `firmware/nu40_lyrics/nu40_lyrics.ino` | 펌웨어. 프레임 수신 → 지구본·가사 상자·막대 그리기 |
| `firmware/nu40_lyrics/hangul_font.h` | 한글 글꼴 2350자 (주식 티커와 같은 파일) |
| `host/lyrics_oled.py` | 본체. 음원 확보·분석·재생·시리얼 전송 |
| `host/lrc.py` | .lrc 해석 + **화면 폭에 맞게 자르기** |
| `host/fetch_lyrics.py` | 유튜브 링크만으로 타이밍 붙은 가사(.lrc) 받아오기 |
| `host/tap_sync.py` | 엔터를 눌러 가사 타이밍(.lrc)을 직접 만드는 도구 |
| `host/radio_fx.py` | 소리를 옛날 라디오처럼 가공 (대역 제한·잡음·깨짐·물먹음) |
| `tools/preview/` | 보드에 굽지 않고 화면을 PC에서 미리 보는 도구 |
| `lyrics/` | .lrc 가사 파일을 두는 곳 |

## 처음 설치

```bash
cd ~/nu40-lyrics/host

# 파이썬 환경 (numpy, pyserial)
python3 -m venv .venv && ./.venv/bin/pip install -q numpy pyserial

# yt-dlp 단독 실행 바이너리 (36MB라 저장소에 없다)
mkdir -p bin && curl -L -o bin/yt-dlp \
  https://github.com/yt-dlp/yt-dlp/releases/latest/download/yt-dlp_macos
chmod +x bin/yt-dlp
```

한글 글꼴은 `firmware/nu40_lyrics/hangul_font.h` 에 이미 들어 있다(갈무리9, 2350자).
미리보기 도구를 쓰려면 갈무리9 TTF 가 `~/Library/Fonts/` 에 있어야 한다.

## 사용법

```bash
cd ~/nu40-lyrics/host

# 보드 없이 터미널에서 확인
./.venv/bin/python lyrics_oled.py "<유튜브 링크>" --lrc ../lyrics/노래.lrc --preview

# 보드로 재생 (노트북에서 소리가 나면서 OLED에 가사가 뜬다)
./.venv/bin/python lyrics_oled.py "<유튜브 링크>" --lrc ../lyrics/노래.lrc

# 로컬 음원 파일도 된다
./.venv/bin/python lyrics_oled.py ~/Music/노래.m4a --lrc ../lyrics/노래.lrc

# 실물로 맞춰 본 소리 설정 (촬영에 쓴 조합)
./.venv/bin/python lyrics_oled.py ~/Music/노래.m4a --lrc ../lyrics/노래.lrc \
    --radio 0.7 --crush 0.6 --water 0.6
```

가사가 소리보다 빠르거나 늦으면 `--offset` 으로 통째로 민다 (양수 = 가사가 빨라짐).

```bash
./.venv/bin/python lyrics_oled.py "<링크>" --lrc ../lyrics/노래.lrc --offset -0.3
```

펌웨어 업로드:
```bash
CLI="/Applications/Arduino IDE.app/Contents/Resources/app/lib/backend/resources/arduino-cli"
"$CLI" compile --fqbn nucode:nrf52:nu40dk firmware/nu40_lyrics
"$CLI" upload  --fqbn nucode:nrf52:nu40dk -p /dev/cu.usbmodemXXXX firmware/nu40_lyrics
```

## 소리 가공 — 옛날 라디오 느낌

`--radio`, `--crush`, `--water` 를 겹쳐서 쓴다. **전부 기본은 꺼져 있다.**
2026-08-19 실물로 들어보며 맞춘 조합은 `--radio 0.7 --crush 0.6 --water 0.6` 이다.

| 옵션 | 하는 일 | 안 쓰면 |
|---|---|---|
| `--radio` | 대역 제한 + 잡음 + 회전 흔들림 + 전파 세기 출렁임 | 원음 그대로 |
| `--crush` | 계단 줄이기(비트 깎기) + 샘플 솎기 | 지글거림 없음 |
| `--water` | 차단 주파수가 일렁이는 저역통과 | 먹먹함 없음 |
| `--dropout` | 소리가 툭툭 끊김 | **기본 꺼짐** |

알아둘 것이 네 가지 있다. 전부 만들면서 측정으로 확인한 것이다.

- **"지직거리는 아날로그"는 잡음 하나로 안 나온다.** 대역 제한이 사실 소리의 정체이고,
  잡음·회전 흔들림은 그 위의 장식이다. 대역 제한 없이 잡음만 넣으면 시끄러운 원곡이 된다.
- **잡음은 대역 제한보다 먼저 얹어야 한다.** 나중에 얹으면 광대역 성분이 다시 들어와
  대역 제한이 무의미해진다. 처음에 순서를 반대로 짰다가, 측정해보니 고역이 원음보다
  **오히려 늘어 있었다.**
- **상한은 곱셈으로 좁힌다.** 빼기로 하면 세기 0.6에서도 8.3kHz라 사실상 안 잘린다.
  곱셈으로 바꾸니 5.4kHz가 됐고, 그제야 저역 −73% / 고역 −32%가 나왔다.
- **`--crush` 를 올리면 `--water` 가 상쇄된다.** 샘플 솎기가 만드는 고음 잡음이
  저역통과로 깎아낸 고역을 도로 채운다 (0.6/0.6에서 고역 −40%였던 것이 0.8/0.8에서 −2%).
  "더 세게"가 항상 더 좋지는 않다.

**막대와 비트는 원음으로 계산한다.** 가공한 소리로 분석하면 잘려나간 양끝 막대가 늘
바닥에 붙고 비트도 죽는다. 효과는 귀로 듣는 쪽에만 건다.

지글거림은 좋은데 끊김만 거슬리는 경우가 많아서 `--dropout` 을 따로 뺐다.
하나로 묶여 있으면 그때 둘 다 포기해야 한다.

## 인트로에 곡 정보 띄우기

첫 가사가 나오기 전 빈 구간에 제목과 가수를 두 줄로 띄운다. `.lrc` 의 `[ti:]` `[ar:]` 를 쓴다.

```
'Find Me!'
The Poles (더 폴스)
```

펌웨어는 **줄바꿈(`\n`)이 들어오면 두 줄로 그릴 뿐**이고, 무엇을 언제 띄울지는 PC가 정한다
(`intro_cue`). 그래서 다른 문구를 넣고 싶어도 펌웨어를 다시 구울 필요가 없다.
제목이 화면보다 길면 가수 줄을 빼고, 그래도 길면 아예 띄우지 않는다.

## 배경 4가지 — 버튼 1~4

배경은 보드 버튼으로 즉시 바꾼다. 지금 배경이 몇 번인지는 같은 번호의 LED 로 알려준다.
PC 와 상관없이 보드 혼자 처리하므로 재생 중에 눌러도 끊기지 않는다.

| 버튼 | 배경 | 비트에 반응하는 것 | 가사 |
|---|---|---|---|
| 1 | 별밤 | 가까운 별만 십자로 반짝인다 | 외곽선 |
| 2 | 동심원 파문 | 한가운데가 밝게 찬다 | 상자 |
| 3 | 카세트 테이프 | 테이프 선이 굵어진다 | 상자 |
| 4 | 도시 야경 | 창문 불이 바뀐다 | 외곽선 |

**가사 표시 방식은 배경이 정한다** (`bgUsesOutline`).

- **외곽선** — 글자 둘레만 검게 두르고 배경 위에 그대로 얹는다. 배경이 다 보인다.
- **상자** — 상자 안을 검게 지우고 그 위에 글자. 어떤 배경에서도 또렷하다.

성긴 배경(별밤·야경)에만 외곽선을 쓴다. 선이 촘촘한 배경(파문·카세트)에 외곽선을 쓰면
글자가 배경 선과 섞여서 안 읽힌다. 렌더링해서 확인하고 정한 것이다.

도시 야경의 건물 높이를 y33 아래로 묶어 둔 것도 같은 이유다. 그보다 높으면 지붕선이
가사(y22~32)를 가로질러 외곽선 글씨를 망친다.

배경 둘레의 반짝임은 PC가 보내주는 **비트 값**(저역 세 칸의 세기)이 만든다.
레퍼런스의 지구본은 그냥 돌지만, 이 배경들은 음악에 맞춰 움직인다.

## 가사 파일(.lrc)은 어떻게 준비하나

`.lrc` 는 `[분:초.백분의일초]가사` 형식의 표준 자막 파일이다.

```
[ti:곡 제목]

[00:12.40]첫 소절
[00:16.10]둘째 소절
```

### 방법 1 — 링크만 주고 자동으로 (가장 빠름)

```bash
./.venv/bin/python fetch_lyrics.py "<유튜브 링크>" --out ../lyrics/노래.lrc
```

**가사 페이지를 검색해서 긁어오지 않는다.** 그렇게 얻는 건 시간표가 없는 맨 글자라
이 프로젝트에는 쓸모가 없다. 대신 처음부터 타이밍이 붙어 있는 출처 두 곳을 순서대로 본다.

1. **LRCLIB** (`lrclib.net`) — 음악 재생기용 동기화 가사 공개 API. 키가 필요 없고
   `[mm:ss.xx]` 형식을 그대로 내려준다. **곡 길이로 대조**해서 같은 제목의 라이브·리믹스를
   잘못 집는 걸 막는다 (15초 넘게 차이 나면 경고).
2. **유튜브 자막** — 그 영상에 달린 자막. 업로더가 넣은 원본 자막이 있으면 가장 정확하고,
   없으면 자동 자막(음성 인식)을 쓴다. 자동 자막은 **글자가 틀릴 수 있다.**

아티스트·곡명은 유튜브 메타데이터에서 먼저 찾고, 없으면 제목에서 짐작한다
(`가수 - 곡명 (Official Video)` 꼴에서 홍보 문구를 걷어낸다). 빗나가면 직접 준다:

```bash
./.venv/bin/python fetch_lyrics.py "<링크>" --artist "가수" --track "곡명" --out ../lyrics/노래.lrc
./.venv/bin/python fetch_lyrics.py "<링크>" --source youtube --lang ko --out ../lyrics/노래.lrc
```

### 방법 2 — 직접 찍기 (자동이 실패했을 때)

가사 **글자**를 한 줄에 한 소절씩 적은 .txt 를 만들어 두고 `tap_sync.py` 로 타이밍만 찍는다.

```bash
# 가사를 한 줄에 한 소절씩 적은 .txt 를 만들어 두고
./.venv/bin/python tap_sync.py "<유튜브 링크>" \
    --text ../lyrics/노래.txt --out ../lyrics/노래.lrc
```

노래가 흐르는 동안 각 소절이 시작되는 순간 엔터를 누르면 된다.
`b`+엔터로 직전 것을 취소하고, `q`+엔터로 여기까지 저장한다.
손이 느려서 항상 조금 늦게 눌린다면 `--lead 0.2` 로 일괄 보정한다.

## 화면에서 글자가 잘리지 않게 하는 방법

이 프로젝트의 핵심 제약이다. **OLED는 128픽셀뿐이다.**

| | 글자 폭 | 한 줄 한계 |
|---|---|---|
| 한글 (갈무리9) | 10픽셀 | **12자** |
| 영문·숫자 | 6픽셀 | 20자 |

가사 상자는 좌우 여백까지 쓰므로 글자가 실제로 쓸 수 있는 폭은 **116픽셀**이다.

이걸 펌웨어에서 잘라내면 문장이 뭉텅 사라진다. 그래서 **PC가 미리 나눈다**
(`lrc.py`의 `split_to_fit`). 띄어쓰기를 먼저 존중하고, 단어 하나가 화면보다 길면
그때만 글자 단위로 자른다. 나뉜 조각들은 그 줄이 차지한 시간을 나눠 갖는다.

시간을 나눌 때 두 가지를 지킨다.

- **조각 시작 시각은 그 줄의 구간을 절대 넘지 않는다.** 최소 표시시간을 억지로 확보하려고
  뒤로 밀면 마지막 조각이 다음 줄을 덮어쓴다. 조금 빨리 지나가도 넘기지 않는 쪽이 맞다.
- **완전한 비례 배분은 쓰지 않는다.** 꼬리가 짧으면 비례만으로는 0.3초만 스치고 사라진다.
  평균값과 반씩 섞어 짧은 조각도 읽을 시간을 갖게 한다.

### 나눌 때 탐욕적으로 채우지 말 것

폭이 찰 때까지 밀어넣고 남은 걸 다음 조각에 버리면 **"꽉 찬 조각 + 고아 한 단어"** 가 된다.
한글은 조사가 붙은 짧은 어절이 많아 이게 특히 자주 터진다. 실제 곡에서 재보니
나뉜 17줄 중 **7줄**이 그랬고, 한 줄은 화면에 **한 글자만** 떴다(`[13자, 1자]`).

그래서 조각 수는 최소로 두되(읽을 시간을 벌어야 하므로), 그 개수 안에서
**폭이 고르게** 나뉘도록 고른다. 목표 폭에서 벗어난 만큼을 제곱해 벌점을 주면
아주 짧은 조각이 크게 불리해져서 고아가 사라진다.

```
0번 줄  [12자, 2자] → [7자, 7자]
11번 줄 [13자, 1자] → [7자, 7자]
고아 조각 7개 → 0개
```

굽기 전에 눈으로 확인하는 방법:

```bash
# 폭이 큰 조각을 배경 4가지로 각각 렌더링한다. 잘리는 건 여기서 다 드러난다.
~/nu40-stock-ticker/.venv/bin/python tools/preview/render_cues.py lyrics/노래.lrc
~/nu40-stock-ticker/.venv/bin/python tools/preview/render_cues.py lyrics/노래.lrc --bg 0

# 배경 시안을 다시 보고 싶으면
~/nu40-stock-ticker/.venv/bin/python tools/preview/bg_options.py
```

펌웨어 글꼴에 없는 글자(KS X 1001 밖의 한글, 특수문자)는 화면에서 빈칸이 된다.
`lyrics_oled.py` 가 시작할 때 미리 경고해 준다.

## 알아둘 것

- **오디오는 반드시 m4a(AAC)로 받는다.** macOS의 `afconvert` 는 WebM/Opus 를 못 읽는다.
  yt-dlp 기본값 `bestaudio` 는 webm 을 고르기 때문에 포맷 셀렉터로 m4a 를 강제한다.
  ffmpeg 불필요.
- **yt-dlp 는 `host/bin/` 의 단독 실행 바이너리를 쓴다.** 시스템 파이썬이 3.9라 pip 으로는
  구버전만 깔리고, 구버전은 유튜브 봇 차단에 403 으로 막힌다. 차단이 재발하면 이것만 다시 받는다:
  ```bash
  curl -L -o host/bin/yt-dlp \
    https://github.com/yt-dlp/yt-dlp/releases/latest/download/yt-dlp_macos
  chmod +x host/bin/yt-dlp
  ```
- **`#include <Adafruit_TinyUSB.h>` 가 없으면 `Serial` 에서 링크 에러가 난다.** 이 보드의 규칙이다.
- **`Wire.setClock(400000)` 을 지우지 말 것.** 기본 100kHz 로는 한 화면 보내는 데 85ms 가 걸려
  12fps 밖에 안 나온다. 막대가 음악처럼 움직이려면 400kHz 가 필요하다.
- **보드는 한 번에 한 프로그램만 물어야 한다.** 뮤직 LED 서버나 메트로놈이 켜져 있으면
  두 프로세스가 같은 포트에 각자 프레임을 쏴서 화면이 엉킨다. `lyrics_oled.py` 가 시작할 때
  `lsof` 로 검사해서 경고한다. 직접 확인하려면 `lsof /dev/cu.usbmodem*`.
- **브라우저는 유튜브 iframe 의 소리를 분석할 수 없다.** 크로스 오리진이라 Web Audio 접근이
  막힌다. 그래서 웹페이지가 아니라 PC 프로그램이 음원을 직접 받아 분석하는 구조를 쓴다.
- afplay 는 실제로 소리가 나기까지 조금 걸린다. 기본 `--latency 0.25` 로 보정해 두었다.
- **UTF-8 끝 다듬기를 길이와 상관없이 돌리지 말 것.** 보드로 보내는 글은 96바이트까지라
  잘릴 때 글자 중간이 끊기지 않게 끝을 다듬는데, 이 규칙을 항상 적용하면 한글 한 글자가
  3바이트에 뒤 두 바이트가 '이어짐' 표시라서 **온전한 글자도 통째로 벗겨진다.**
  이 버그로 한글로 끝나는 가사가 전부 마지막 한 글자씩 사라졌다. 영문으로 끝나면 안 걸려서
  발견이 늦었다. 지금은 한 번 디코딩했다 되돌려서 **끝이 불완전할 때만** 떨어지게 한다.
- **오디오 전용 AAC 가 없는 영상이 있다.** 그런 영상은 opus 하나만 주고 AAC 는 영상과
  합쳐진 포맷 안에만 있다. m4a 만 고집하면 "해당 포맷 없음"으로 멈추므로 합쳐진 mp4 까지
  받는 길을 열어 뒀다. 그래도 403 으로 막히는 영상이 있는데, 그때는 로컬 음원 파일을 쓴다.
- **아티스트 이름의 괄호 병기를 떼고 다시 조회한다.** 한국 음악 영상은
  `The Poles (더 폴스)` 처럼 영문·한글을 나란히 적는 일이 많은데, 가사 데이터베이스에는
  보통 한쪽 표기로만 올라가 있다. 병기한 채로 물어보면 있는 곡도 못 찾는다.
- 디코딩한 WAV 는 원본 옆이 아니라 `host/.cache/` 에 만든다. 남의 폴더를 어지르지 않는다.

## 화면 배치

```
 y  0~43   배경 4가지 중 하나. 버튼 1~4로 전환. 비트에 반응한다
 y 18~35   가사 — 배경에 따라 외곽선 또는 상자
 y 44~63   주파수 막대 16개 (폭 6, 간격 2). 올라갈 땐 즉시, 내려올 땐 천천히
```

가사가 없는 구간(간주)에는 상자를 그리지 않는다. 배경과 막대만 계속 움직인다.
PC가 3초 넘게 조용하면 `대기중` 으로 돌아간다.

## 시리얼 프레임

```
막대 : 0xAA 0x55 0x01 [막대 16바이트][비트 1바이트] [체크섬]   30fps
가사 : 0xAA 0x55 0x02 [길이] [UTF-8 바이트] [체크섬]          바뀔 때만
보드→PC : BG|n  (버튼으로 배경을 바꿨을 때)
```
체크섬은 종류 바이트부터 마지막 값까지 전부 XOR. 값이 맞을 때만 반영한다.

## 아직 안 한 것

- 재생 조작(일시정지·다음곡). 버튼 4개를 배경 전환에 다 썼으므로, 필요하면 길게 누르기로
  구분하거나 PC 쪽에서 처리해야 한다.
- 긴 제목을 옆으로 흘려 보여주는 스크롤. 지금은 화면보다 길면 그냥 안 띄운다.
